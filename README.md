# Chess Analysis (Анализ Шахматных Партий)

Система глубокого анализа и интерактивного разбора шахматных партий в стиле Chess.com Game Review, функционирующая на базе шахматного движка Stockfish с нейросетевой оценкой NNUE.

> **Авторство проекта**:  
> Программа полностью спроектирована и разработана искусственным интеллектом **Antigravity (Google DeepMind)** в режиме парного программирования в соответствии с техническими требованиями, спецификациями и задачами пользователя.

---

## Возможности и архитектура

Приложение разработано для Windows Desktop на платформе .NET 10 (C#, Windows Forms) с собственной векторной графикой и тёмной темой интерфейса.

Ключевой функционал:
- Интерактивная шахматная доска с подсветкой легальных ходов, полей последнего хода, стрелок лучших ходов и угроз соперника, а также пользовательских графических пометок (стрелки и круги правой кнопкой мыши).
- Живой анализ партии в реальном времени с динамической оценкой позиций, вычислением вероятности победы и графиком преимущества (Eval Bar и график над доской).
- Детальный отчет по завершении анализа партии: распределение точности по ходам, расчет перформанс-рейтинга (Performance Elo), классификация ходов по категориям, фазовый анализ (дебют, миттельшпиль, эндшпиль) и тренерские комментарии к каждому ключевому ходу.
- Импорт партий через PGN-файлы, буфер обмена или прямую загрузку недавних партий с платформ Chess.com и Lichess по никнейму игрока.
- Многопоточный анализ Stockfish с поддержкой многолинейного поиска (MultiPV 1–5 линий) и настройкой потоков CPU.

## Математическая система оценки точности CAPS

В основе системы оценки лежит математическая модель **CAPS** (Computer Accuracy Percentage Score), позволяющая объективно оценить качество игры независимо от исхода партии.

### 1. Преобразование сантипешек в вероятность победы

Оценка позиции от Stockfish выражается в сантипешках ($cp$, где 100 cp = 1 пешка). Сантипешки переводятся в вероятность выигрыша $P(\text{win}) \in [0, 100]\%$ по логистической сигмоиде:

$$P(\text{win}) = \frac{100}{1 + 10^{-\frac{cp}{400}}} = \frac{100}{1 + e^{-0.00575646 \cdot cp}}$$

Характерные точки кривой:
- $cp = 0$ (равная позиция): $P = 50.0\%$
- $cp = +100$ (преимущество в пешку): $P \approx 64.0\%$
- $cp = +300$ (преимущество в легкую фигуру): $P \approx 85.0\%$
- $cp = +800$ (подавляющий перевес): $P \approx 99.0\%$
- Форсированный мат: $P = 100\%$ для матующей стороны и $0\%$ для защищающейся.

Для черных вероятность победы зеркальна: $P_{\text{black}} = 100 - P_{\text{white}}$.

### 2. Потеря вероятности победы (Delta P)

Для каждого сделанного в партии полухода рассчитывается падение шансов на победу относительно оценки позиции до хода:

$$\Delta P = \max(0,\; P_{\text{before}} - P_{\text{after}})$$

### 3. Точность отдельного хода (Move Accuracy)

Точность каждого хода определяется по экспоненциальной функции зависимости от $\Delta P$:

$$\text{Accuracy} = \min\left(100.0,\; \max\left(0.0,\; 103.1668 \cdot e^{-0.04354 \cdot \Delta P} - 3.1669\right)\right)$$

- Ход первой линии движка ($\Delta P = 0$): $100.0\%$
- Незначительная помарка ($\Delta P \approx 5\%$): $\approx 80.0\%$
- Серьезная ошибка ($\Delta P \ge 35\%$): $0.0\%$

### 4. Итоговая точность партии и перформанс-рейтинг

Итоговая точность игрока за партию вычисляется как среднее значение точности всех ходов за вычетом ходов дебютной книги, скорректированное штрафным коэффициентом за допущенные ошибки:

$$\text{Penalty} = \frac{6.0 \cdot N_{\text{blunders}} + 3.0 \cdot N_{\text{mistakes}} + 0.8 \cdot N_{\text{inaccuracies}}}{N_{\text{total}}} \times 20.0$$

$$\text{Accuracy}_{\text{game}} = \min\left(99.8,\; \max\left(10.0,\; \text{Accuracy}_{\text{base}} - \text{Penalty}\right)\right)$$

Расчет перформанс-рейтинга (Performance Elo) калибруется по базовой сигмоиде точности с привязкой к рейтингу игрока и модификаторами за допущенные зевки, качество победы и наличие сильных ходов.

## Классификация ходов и критерии оценивания

Классификатор ходов (`MoveClassifier.cs`, `MoveClassificationWeights.cs`) разделяет все сыгранные ходы на 11 категорий:

| Название | Символ | Код | Описание и пороговые условия |
|---|:---:|:---:|---|
| **Блестящий (Brilliant)** | `!!` | `G1` | Лучший ход первой линии Stockfish с реальной жертвой материала (фигура ходит под бой более слабой фигуры или оставляется без защиты), сохраняющий решающий перевес либо ведущий к форсированному мату (включая спёртый мат `Qb8+!!`). Защищен от ложных срабатываний: ход под шахом никогда не является жертвой. |
| **Замечательный (Great)** | `!` | `G2` | Единственный ход, сохраняющий перевес или спасающий партию, когда вторая линия движка существенно отстает по оценке ($\Delta \ge 240$ cp). |
| **Лучший (Best)** | `★` | `N1` | Совпадает с первой линией шахматного движка Stockfish. |
| **Отличный (Excellent)** | `👍` | `N2` | Ход из топ-3 линий движка с отставанием не более 140 cp и потерей $\Delta P \le 10.5\%$. |
| **Неплохой (Good)** | `✓` | `N3` | Надежное продолжение (линии 2–4) с потерей $\Delta P \le 13.0\%$. |
| **Теоретический (Book)** | `📖` | `G3` | Ход по дебютной энциклопедии ECO (до 15 хода с потерей $\Delta P \le 15\%$). |
| **Вынужденный (Forced)** | `□` | `M1` | Единственный возможный легальный ход в позиции. |
| **Неточность (Inaccuracy)** | `?!` | `B1` | Ход с потерей $10\% \le \Delta P < 20\%$. |
| **Ошибка (Mistake)** | `?` | `B2` | Позиционное ухудшение ($240 \le \text{cp}_{\text{loss}} < 300$ или $20\% \le \Delta P < 30\%$) без отдачи фигуры за бесплатно и без допуска форсированного мата. |
| **Упущенный шанс (Missed Win)** | `✖` | `B4` | Пропуск решающего выигрывающего продолжения из позиции с перевесом $\ge 200$ cp или $P \ge 72\%$. |
| **Зевок (Blunder)** | `??` | `B3` | Прямая отдача фигуры без компенсации с потерей материала $\ge 150$ пунктов, либо допуск форсированного мата сопернику из небознадежной позиции. |

### Алгоритм выявления жертв (Brilliant Move):
1. Ход обязан быть первой линией Stockfish (`isTopEngineMove`).
2. Король игрока до хода не находится под шахом (`!wasInCheck`): уход от шаха или перекрытие трактуются как обязательная защита.
3. Проверяется факт жертвы материала:
   - Прямая жертва: фигура ставится под бой фигуры меньшей ценности (ферзь под ладью/коня/слона/пешку, ладья под легкую фигуру/пешку, легкая фигура под пешку) либо на незащищенное поле с дефицитом размена $\ge 150$ cp.
   - Косвенная жертва: ход отвлекает защиту от другой собственной фигуры ценностью не ниже легкой.
   - Жертва с форсированным матом: жертва тяжелой или легкой фигуры, форсирующая мат за $N$ ходов.
4. Позиция до хода не является безнадежно тривиальной ($preEval \le +12.00$ пешек либо форсированный мат), что сохраняет распознавание блестящих комбинаций и вскрытий в глубоких атаках на короля.

### Разграничение Зевка и Ошибки:
1. **Зевок (`Blunder`, `??`)** фиксируется при:
   - Доказанной тактической потере фигуры без компенсации (`IsPieceBlundered`, дефицит $\ge 150$ cp).
   - Допуске форсированного мата сопернику из небознадежной позиции.
   - Катастрофическом обрушении позиции из равной/выигрышной в безнадежную (оценка после хода падает до $\le -7.50$, например с 0.0 до -9.8).
2. **Ошибка (`Mistake`, `?`)**:
   - Умеренное позиционное ухудшение (потеря 200–400 cp или $\Delta P < 35\%$), когда фигура не отдана и позиция не обрушена в безнадежную (оценка лучше $-7.50$).

## Взаимодействие со Stockfish по протоколу UCI

Взаимодействие с движком реализовано через асинхронный межпроцессный обмен (`StockfishEngine.cs`):

1. **Инициализация:**
   - Передача команды `uci` и ожидание ответа `uciok`.
   - Установка параметров: `setoption name Threads value <N>`, `setoption name Hash value <M>`, `setoption name MultiPV value <K>`, `setoption name UCI_AnalyseMode value true`.
   - Проверка готовности через `isready` / `readyok`.

2. **Запрос анализа:**
   - Позиционирование: `position fen <FEN-строка>`.
   - Запуск расчета: `go depth <D> nodes <N>`.

3. **Обработка потока данных:**
   - Движок возвращает строки вида `info depth ... multipv ... score cp <value> pv <moves>` или `score mate <N>`.
   - Парсер преобразует данные в структуры `EngineEvaluation` и `EngineLine`.
   - Завершение расчета фиксируется строкой `bestmove <uci>`.

## Установка шахматного движка Stockfish

Для работы анализа требуется исполняемый файл Stockfish:
1. Загрузите сборку Stockfish для Windows с официального сайта: [https://stockfishchess.org/download/](https://stockfishchess.org/download/).
2. Создайте каталог `C:\Stockfish\` и поместите в него исполняемый файл (например, `stockfish.exe`).
3. При старте программа автоматически проверяет каталог `C:\Stockfish\`. При необходимости путь к движку можно переназначить в меню настроек приложения (кнопка настроек в правом верхнем углу).

## Сборка и запуск

Проект собирается с помощью .NET 10 SDK:

```bash
# Сборка Release-версии Windows Desktop
dotnet build ChessAnalysis/ChessAnalysis.csproj -c Release

# Запуск тестов
dotnet run --project ChessAnalysis.Tests/ChessAnalysis.Tests.csproj

# Публикация автономного единого исполняемого файла (.exe)
dotnet publish ChessAnalysis/ChessAnalysis.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o dist/ChessAnalysis_SingleFile
```

Исполняемый файл после публикации находится по пути: `dist/ChessAnalysis_SingleFile/ChessAnalysis.exe`.

В каталоге `scripts/` содержатся готовые командные файлы:
- `scripts/BuildAndRun.bat` — сборка и запуск приложения.
- `scripts/Run.bat` — быстрый запуск скомпилированной версии.
- `scripts/PublishRelease.bat` — сборка Single-File дистрибутива.

## Модульное тестирование

Проект покрыт 13 автоматическими тестами в `ChessAnalysis.Tests`:
- Проверка генератора легальных ходов, рокировок, взятия на проходе и превращений (`BoardState`).
- Парсинг PGN-партий с метаданными и временными метками (`PgnParser`).
- Быстрый поиск дебютов по базе ECO.
- Модели CAPS: логистическая функция $P(\text{win})$ и расчет точности.
- Верификация правил MoveClassifier: спёртый мат `Qb8+!!`, блокировка ложных бриллиантов под шахом, корректное разграничение `Mistake` и `Blunder`.
- Звуковая подсистема и интерфейсные компоненты.
